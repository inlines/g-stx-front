# Game StockX — frontend

Angular 22.1, NGXS 22, TypeScript 6. Backend: отдельный Rust API.

## Локальный запуск

Нужен Node.js 24.19.0 (зафиксирован в `.nvmrc`). Старые Node.js 20 и 22.12 не поддерживаются Angular 22.

```bash
nvm install
nvm use
npm ci
npm start
```

Приложение: http://localhost:4200. В development API ожидается на
`http://127.0.0.1:9090/api`, WebSocket — `ws://localhost:9090/ws/`.
Адреса находятся в `src/app/environments/environment.dev.ts`.
Production использует относительные `/api` и `/ws/`, которые должен проксировать сервер.

После обновления Angular ранее запущенный dev-server нужно остановить и запустить заново.

## Проверки

```bash
npm run typecheck
npm test
npm run build
```

Тесты работают через официальный Angular Vitest runner в jsdom, без установленного Chrome.
`npm run test:watch` запускает их в режиме наблюдения. HTTP-тесты проверяют контракт запросов
с подменой транспорта; они не заменяют проверку работающего Rust API.
Результат production-сборки: `dist/game-stockx/browser`.

Дисковый кэш Angular временно отключён в `angular.json`: нативный LMDB 3.5.6 на локальной
macOS аварийно завершал процесс. Это влияет на скорость повторной сборки, а не на приложение.
После исправления совместимости LMDB кэш можно включить снова.
Лимит предупреждения размера initial bundle сохранён: 500 kB, максимальный — 2 MB.

## Организация кода

- `components` — страницы и элементы интерфейса; страницы загружаются через `loadComponent`.
- `states` — NGXS-состояния, actions, типизированные HTTP-сервисы и модели API.
- `shared/list-params.ts` — нормализация и сравнение параметров списков; только поля,
  поддерживаемые API: `cat`, `limit`, `offset`, `query`, `sort`, `ignore_digital`.
- `shared/personal-list.controller.ts` — общий жизненный цикл коллекции, wishlist и WTS:
  выбор платформы, загрузка и обновление после успешной операции.
- `shared/collection-filter.ts` — чистая локальная фильтрация и сортировка коллекции.
- `environments/environment.token.ts` — типизированная конфигурация API/WebSocket.
- `testing` — общие test providers и проверки контракта API.

Поиск каталога отправляется после паузы 300 мс. Изменение фильтра сбрасывает страницу,
выбор платформы обновляет параметры одной операцией, предыдущий запрос отменяется.
Сохранённая страница восстанавливается при возврате. Неиспользуемые фильтры разработчика,
издателя и франшизы удалены: backend их не обрабатывает. Сортировки каталога — имя и дата;
коллекция дополнительно сортируется по цене локально. Нулевая цена сохраняется как 0.

Публичные маршруты, HTTP payload, имена NGXS state и существующие actions сохранены.
WTS («Хочу продать») использует те же карточки и пагинацию, что и вишлист.
В своей коллекции пользователь выставляет релиз на продажу или снимает отметку.
Снятие с продажи не удаляет игру из коллекции; удаление из коллекции снимает и WTS.
Для работы необходим backend с миграцией `users_have_wts` и полями `wts_count` /
`wts_ids` в `/collection-stats`. При выставлении открывается окно с необязательной
ценой продажи (целое число рублей, включая 0) и отметкой CIB — полный комплект.
Кнопка «Изменить» в WTS открывает сохранённые условия. API `/add_wts` сохраняет
`price` и `cib`, `/wts` возвращает их. Цена покупки остаётся отдельной.

## Ручная проверка

1. Открыть каталог, набрать поиск, быстро переключить платформу; проверить страницу и результаты.
2. Перейти на вторую страницу, открыть игру и вернуться; проверить восстановление списка.
3. Войти, открыть коллекцию и wishlist, переключить платформы и сортировку коллекции.
4. На тестовой игре проверить добавление/удаление и сохранение цены, включая 0.
5. Проверить карточки коллекционеров, выход и повторный вход; при наличии второго аккаунта — чат.

## Коллекция и вишлист

Оба экрана используют `PersonalLibraryComponent` и `ReleaseCardComponent`:
адаптивные карточки, страницы по 24/48/96 релизов и общие состояния загрузки/ошибки.
Поиск, сортировки, цены и сумма расходов остаются в коллекции. Серийники открываются
нажатием на заголовок (также с клавиатуры); наведение показывает первые три.

Параметры отображения и позиция прокрутки сохраняются при переходе в карточку игры
и обратно в течение сессии приложения. Смена платформы или фильтра сбрасывает страницу.
Поиск и сортировка по цене выполняются до разбивки на страницы по полному списку:
HTTP-сервис догружает его порциями по 1000 через существующие `limit`/`offset` и
`total_count`. До окончания загрузки показывается индикатор, при ошибке — повтор.
Это пагинация отображения; серверный контракт не менялся.


## Стили и размер загрузки

Bootstrap остаётся основой сетки, responsive-утилит, форм и оформления
компонентов ng-bootstrap. Подключается выборочно через `src/styles/bootstrap.scss`
в исходном порядке и с исходными значениями переменных. Полная utility API
сохранена, автоматического удаления классов по шаблонам нет: динамические классы
Angular и ng-bootstrap не должны исчезать при сборке. При добавлении нового
Bootstrap-компонента добавьте его SCSS-модуль в этот файл. Bootstrap JavaScript
отдельно не подключается: поведением управляет Angular/ng-bootstrap.

- Общие базовые стили: `src/styles.scss`.
- Общий mixin фокуса: `src/styles/_controls.scss`; вызывается внутри компонентов,
  сохраняя селекторы, специфичность и итоговый CSS.
- Единственный использовавшийся эффект из animate.css сохранён в
  `src/styles/_seller-animation.scss`, включая reduced-motion и печать.
- Повторяющийся логотип: `public/icons.svg#brand`. Остальные небольшие SVG
  оставлены inline: это позволяет сохранить локальные стили и не создавать
  отдельный запрос для каждой уникальной иконки.

Контрольная production-сборка после оптимизации (10.09.2026): глобальный CSS
307,08 → 179,05 КБ; стартовые JS+CSS 876,51 → 745,99 КБ без сжатия. Оценка
передаваемого объёма от Angular: 182,34 → 173,28 КБ. Это размеры сборки, а не
замер времени отрисовки или скорости на реальном телефоне. Предупреждение
о превышении бюджета 500 КБ сохраняется; бюджет не повышался.

Проверки: `npm run typecheck`, `npm test`, `npm run build -- --stats-json`.
При изменении набора SCSS проверяйте также модалки, tooltip, toast, accordion,
carousel, состояния форм и мобильную сетку: часть классов создаёт ng-bootstrap.

Заявки на серийники поддерживают PS2 (8), PS3 (9), PS4 (48), PS5 (167), PSP (38).
PS1 имеет ID 7 и не поддерживается. Исправление ID есть также в backend;
для полноценного исправления необходимо обновить оба приложения. Миграция БД
для этого изменения не нужна.
